# NODE_7388 scroll chapter

The original Hero typography, navbar, palette and CTA composition are retained.
`Hero` and `FeaturedProject` remain Server Components passed through the small
`HeroMotion` client boundary. `NodeScene` lazily mounts an isolated R3F Canvas.

## Geometry

`Node7388` contains six matching framed acrylic panels. Each has an open graphite
PCB perimeter, two small connectors, cyan right-angle traces and chrome rails.
The open PCB centers keep the graphite SYS_CORE processor visible. There are no
external GLBs, HDRIs, fonts, Spline scenes or texture network requests.

| Face | Local normal | Subsystem |
| --- | --- | --- |
| Front | +Z | WEB / INTERFACE |
| Back | -Z | API / SERVICES |
| Right | +X | AI / INFERENCE |
| Left | -X | DATA |
| Top | +Y | SYSTEM / CONTROL |
| Bottom | -Y | INFRASTRUCTURE |

The cube has a fixed, restrained three-quarter orientation. Faces translate only
along their local normals. Rails and data buses extend with the panels. SYS_CORE
stays at the origin during explosion; the rear assembly recedes slightly during
project focus. The front PCB stays square and scales proportionally.

## Timeline

One ScrollTrigger pins for 330vh, with scrub 0.8 and anticipatePin 1.
One timeline unit corresponds to the original chapter's 150vh.

| Timeline units | Behavior |
| --- | --- |
| 0–1 | Original identity recede and stage centering; original timings retained |
| 1–1.12 | Center lock; SYS_CORE / STABLE and DATA_BUS / ONLINE |
| 1.12–1.52 | Six-axis mechanical separation |
| 1.55–1.95 | Front WEB face approaches the project target and faces the camera |
| 1.95–2.13 | Aligned 3D display crossfades into the DOM project surface |
| 2.13–2.2 | Stable project hold |

Progress is stored in a context ref, not React state. GSAP writes `explode`,
`focus` and `handoff`; R3F reads these values in `useFrame`. Reverse scrolling
reconstructs every stage. The scoped GSAP context, matchMedia setup, callbacks and
pending refresh frame are cleaned up on unmount.

## Handoff

The front PCB rotates toward an identity quaternion while a separate thin display
opens in front of it. The square PCB fades behind that display without being
stretched. Actual `[data-project-screen]` and Canvas bounding rectangles are
converted into orthographic world coordinates, accounting for the inherited
stage scale. At focus = 1 the display matches the DOM screen's center and size.
Only then does the DOM surface crossfade over the same rectangle. Rear panels
remain on their original axes, faintly visible beyond the project edges.

Canvas uses `resize.offsetSize` so the Hero's CSS transform cannot feed back into
the renderer's layout measurements. The stage destination is measured on
ScrollTrigger refresh. Fonts and Canvas readiness request a refresh.

## Performance and fallbacks

- DPR capped at 1.5; orthographic camera; demand rendering, invalidated by GSAP.
- No postprocessing, shadows, bloom, continuous spin or scroll-driven React state.
- Each PCB's circuit traces are batched into one line geometry.
- Clearcoat/transparent acrylic approximates glass without expensive transmission.
- Below 1024px or with reduced motion: SVG NODE, no Canvas/pin, project in normal flow.
- Unavailable/lost WebGL or a Canvas error: static NODE and unpinned accessible project.
- Canvas loading uses the same SVG within the reserved stage dimensions.
- Work links jump to the project chapter when enhanced; native anchor behavior in fallback.

## Validation

Production build, lint and TypeScript checks pass. Browser checks covered 1280,
1440 and 1728 × 900: one pin spacer, no horizontal overflow, centered stage error
below 0.001px, fixed navbar and full reverse restoration. Reloads reconstruct one
working trigger; in the test browser reload returned to the top, and the entire
chapter remained traversable afterward. Reduced motion, 390px mobile, disabled
WebGL and simulated context loss all show the unpinned, accessible project.
Delaying the Canvas chunk keeps the loading illustration visible with no stage
height change. No application console errors were recorded. Visual checks used
headless Chromium software WebGL; desktop GPU frame-rate profiling is not claimed.
